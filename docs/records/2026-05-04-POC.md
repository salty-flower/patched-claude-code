# 2026-05-04 — Initial POC: viability of v2.1.88 as audit Rosetta

## Question

Can we anchor patches to a single leaked Claude Code reference version
(v2.1.88) and still meaningfully audit later releases — i.e. is the
function-level structural alignment between v2.1.88 minified and a later
minified bundle good enough to recover the original TS intent for most of
the bundle?

## Method

1. Recovered the v2.1.88 npm artefact (yanked from registry) from
   `Bo1202/claude-code-source` on GitHub. Verified `cli.js` (13 MiB) and
   `cli.js.map` (60 MiB, 4756 sources, full `sourcesContent`) match the
   jsdelivr metadata for v2.1.88.
2. Confirmed sourcemap precision is token-level via
   `experiments/decode-mappings.py`: `gen[L:C]` slices in `cli.js` line up
   with the corresponding TS positions for `AskUserQuestion`,
   `EnterPlanMode`, `ExitPlanMode`, `channelNotification.ts`.
3. Compared v2.1.88 minified against v2.1.112 minified at the AST level
   via `experiments/align.ts` (uses `@babel/parser`). For each top-level
   declaration, computed:
   - kind (Function/Class/Variable/Expression)
   - AST-node-type histogram (cosine similarity)
   - bag of human-authored string literals (Jaccard similarity)
   Identifier names were excluded — they reminify per release.

## Findings

| Best Jaccard(v112 → v88) | Decls | Bytes | % bytes |
| --- | --- | --- | --- |
| ≥ 0.8 (near-identical) | 8 282 | 9.9 MiB | **76.2%** |
| 0.6 – 0.8 (small change) | 304 | 0.5 MiB | 3.8% |
| 0.4 – 0.6 (medium change) | 268 | 0.3 MiB | 2.0% |
| 0.2 – 0.4 (large change) | 235 | 0.2 MiB | 1.6% |
| < 0.2 (novel) | 289 | 0.3 MiB | 2.4% |
| zero literal (small helpers) | 10 148 | 1.8 MiB | 14.0% |

- Token-level sourcemap precision is intact for v2.1.88. Each minified
  position resolves to a `(source-file, line, column)` tuple.
- ~76% of v2.1.112 by bytes is structurally near-identical to v2.1.88
  modulo identifier renaming. These declarations are **trivially
  alignable** to a v2.1.88 source — no LLM lift needed.
- ~7% requires differential lift (small/medium/large change) where v2.1.88
  is a genuine prior.
- ~2.4% is genuinely novel code that has no v2.1.88 prior; cold deminify
  territory.
- ~14% is small zero-literal helpers — fingerprint-invisible, but also
  carry no human-authored content (no tool names, no permission strings),
  so they are out of scope for audit.

## Concrete validation: the channels gate

`AskUserQuestion`'s `isEnabled()` function in v2.1.112 minified is:

```
isEnabled(){if(qj().length>0)return!1;return!0}
```

v2.1.88 minified for the same gate (modulo identifier rename
`qj` ↔ `eH`):

```
isEnabled(){if(eH().length>0)return!1;return!0}
```

v2.1.88 sourcemap pivots to TS source:

```typescript
isEnabled() {
  // When --channels is active the user is likely on Telegram/Discord, not
  // watching the TUI. The multiple-choice dialog would hang with nobody at
  // the keyboard. Channel permission relay already skips
  // requiresUserInteraction() tools (interactiveHandler.ts) so there's
  // no alternate approval path.
  if ((feature('KAIROS') || feature('KAIROS_CHANNELS')) && getAllowedChannels().length > 0) {
    return false;
  }
  return true;
}
```

This is the audit grade we wanted: the comment, the original feature flags
(stripped at build time by Bun's `bun:bundle` macros), and the typed
identifier names are all recovered for free.

## Decision

Project is viable as scoped. Set up:

- `reference/v2.1.88/{cli.js, cli.js.map, sources/}` as the frozen baseline.
- `tools/align.ts` for patch authoring, `tools/verify-patches.ts` for CI.
- `patches/*.toml` files with `rationale_ref` pointing at
  `reference/v2.1.88/sources/`.

Out of scope for v0:

- Mass deminification of v_new — the project ships a small targeted patch
  set, not a full TS reconstruction.
- Bun-binary repacking — patched JS runs on a separately-installed Bun
  runtime when the target ships as a Bun standalone.
- AST-level patches — bytes-level locator/replacement is enough for current
  needs and is robust against AST library churn.

## Inputs preserved

`experiments/` keeps the POC scripts that produced these numbers. Re-run
them on any future release to re-confirm the alignment regime.
