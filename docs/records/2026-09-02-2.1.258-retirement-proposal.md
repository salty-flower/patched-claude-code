# 2.1.258 Patch Retirement Proposal

## Scope

Target `2.1.258` obligations whose behavior upstream replaced or subsumed
during the 2.1.252-2.1.258 window. This record is evidence for a proposal,
not maintainer acknowledgement. The exact retirement set is bound by the
target ledger's proposal digest.

## Runtime Rejection

### `explicit-macos-keychain` plugin evaluation

The 2.1.220-2.1.251 patch invariant routed plugin child-process credential
materialization through the explicitly selected secure-storage abstraction
instead of copying `.credentials.json` from the default login Keychain.

At 2.1.258 upstream replaced the plaintext credential file handoff with a
parent-side secure-storage lookup plus credential file-descriptor injection:

- The plugin parent reads OAuth through the supplied credentials object and
  builds an FD-based child environment:
  `if(D()!=="windows")return{env:{[e.kind==="gateway"?"CLAUDE_CODE_GATEWAY_TOKEN_FILE_DESCRIPTOR":"CLAUDE_CODE_OAUTH_TOKEN_FILE_DESCRIPTOR"]:String(yf),...n},viaFd:!0`
  (darwin graph, chunk-5y0gg3gy.js).
- The child now receives isolated credentials through an FD and a freshly
  constructed environment; no `.credentials.json` materializer remains in the
  eval path for the patched bridge to gate.

The replacement was incomplete. A real macOS runtime test supplied conflicting
`ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` values and observed the child
send the inherited auth token instead of the selected-Keychain OAuth token.
The parent-side selector returned before reading secure storage, so the child
never received the FD credential or the associated environment scrub.

Both obligations remain ported through
`explicit-macos-keychain-plugin-eval-2-1-258`. The patch makes explicit
Keychain selection outrank inherited API credentials while retaining upstream's
secure-storage read, refresh, FD injection, and child-environment isolation.

## Proposed Retirement

### `statusline-footer-control` / `statusline-footer-control-mode-hint-state`

The historical state-carrier lineage injected a vim-mode state indicator
selector into the prompt footer-left side. At 2.1.258 the complete
state-to-render seam is local to the ported dense/narrow hint entries:

- 2.1.258 darwin `function c7` (linux `function b7`):
  `const Fnt=!h9t&&!WP,Bnt=!w9t&&!WP,Unt=!w9t&&WP,Hnt=CB==="VISUAL"||CB==="VISUAL LINE"`
- The active 2.1.258 mode-hint and mode-hint-narrow mappings already inject
  their selectors at this expression; the standalone state carrier adds no
  independent behavior (`statusline-footer-control.toml` 2.1.258 entries,
  darwin+linux).

The permission-mode hiding behavior itself remains ported; only the standalone
state-carrier lineage is retired.

## Proposed Decision

Retire the one obligation above at target 2.1.258.
Keep every currently ported 2.1.258 obligation fail-closed.

The exact retirement set is bound by the target ledger's proposal digest.
