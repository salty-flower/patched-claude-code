### Resume Default Model for `[1m]`

The Darwin resume implementation is `function O(e,o)` in
`chunk-jxkvvx8w.js` at byte offset 10874; its helper imports are from
`chunk-twxt3h9y.js`.
The Linux implementation is at the same byte offset in
`chunk-8sjzywdh.js`, with helpers from `chunk-5khn4tvf.js`.
Darwin chunk hashes are
`2a00a9a9a7616470bc3133e24190cd2d5810944c7249906a0a144f30fde586a3` and
`f415adc86ef06cb3b07bd4988849762d1efa205958cf04a2919e18c910952c6d`;
Linux chunk hashes are
`d0f056ebd0124c4dd94d761845bf7cde444b2fc0300dc24329364ec9008adcd0` and
`df39f0e2a1617a98919a7f240a04bebb6c3ebc36403aa34f0d3f8fecd2249b59`.

The native path resolves `[1m]` using the explicit transcript model `o` only.
When `o` is absent, it ignores the configured default already resolved by
`sh()`/`oh()`, so alias and family comparisons cannot see a default `[1m]`
model.
Transcript `modelId` fallback does not cover transcripts without that
metadata.
The target patch resolves `n0=o??sh()`/`n0=o??oh()` before alias handling.
The locator and rationale checks passed, and static render assertions passed
on both platforms.
A local stub regression compared raw and patched 2.1.281 requests with an
Opus 5.5 `[1m]` environment default and no explicit model selection.
Both retained the 1M beta header.
An instrumented candidate that removed the environment-default guard lost
that header, so the guard change was reverted.
This test protects the existing behavior but does not establish a runtime
effect for the retained `o??sh()`/`o??oh()` replacement.
The observed settings-backed resume already passed `opus[1m]` as the host model;
the no-settings case passed a null host model and resolved `sh()` to null.
Retirement is a review candidate if no reachable state can be shown where the
host model is null but `sh()` supplies a `[1m]` default.
