## Resource extraction and native segmentation

The 2.1.290 `SKILL_FILES` export uses a local alias in a literal object spread.
The earlier static resource extractor reported that spread as one blocking gap per platform.

The extraction fix statically resolves local aliases to literal object expressions and flattens literal spread elements.
It detects alias cycles and leaves dynamic spreads as blocking gaps.
It does not execute bundle source.
The focused extractor suite passed nine tests.

The static target manifest now reports 352 built-in resource entries and zero gaps.
Its partial-scope designation remains part of the result; zero gaps applies to the audited dependency inventory.

Native CellSegmenter captures cover Claude Code 2.1.290 on Darwin arm64 and Linux x64 with Bun 1.4.3.
The genuine Darwin capture from CI run `37399890229` was repeated twice with byte-identical oracle output.
Its native binary hash matches the checked-in Darwin oracle fixture.
The native Linux sample payload matches the Darwin payload.

Both platforms agree on 48 corpus cases, 30 capacity cases, 20 segmentation regressions, and eight paint regressions.
The canonicalized capture payload hash is `f2c0ba98dfa09f431089ef666a5cc4e591afa1f328462722d36700c8fb9927ed`.
The tracked Darwin fixture is [bun-ant-cell-segmenter-oracle.json](../../tools/test/fixtures/bun-ant-cell-segmenter-oracle.json).

## Prompt and telemetry boundaries

The new `client_data.remove_prompt_strings` consumer could apply cached server-provided deletion strings without the existing served-text opt-in.
The 2.1.290 patch gates that cached fallback on `CLAUDE_CODE_ALLOW_SERVED_TOOL_TEXT="1"` before reading the cache.

The explicit local `CLAUDE_CODE_REMOVE_PROMPT_STRINGS` setting remains higher priority, including an empty list that disables the cached source.
The patch does not change bootstrap fetching, cache storage, or endpoints.
Focused tests verify that unapproved cached data causes no cache read or prompt rewrite, while local overrides and explicit opt-in retain their behavior.

The request-body gate did not cover the independent response helper.
The 2.1.290 variants suppress both request-body and response-body capture, including response-file indexing.
This closes the raw-body path addressed by these entries; it does not remove global telemetry.

Assistant-response logging continues to require its explicit setting.
Other telemetry remains governed by its existing feature settings and traffic controls.
