# Claude Code 2.1.301 privacy audit

## Unpatched evidence and patch acceptance

Static review of staged unpatched 2.1.301 against 2.1.296, on Darwin ARM64 and Linux x64.
Three independent reviewers used the shared `dist/anti-trace-dossier-2.1.301.json`, generated by `bun dist/generate-301-dossier.ts`, then inspected focused module slices.
The dossier records module hashes, UTF-16 offsets, byte offsets, snippets, decoded constants, endpoints, and search commands.
After worker-URL materialization was finalized, the regenerated dossier SHA-256 is `a6a97f57fa562949021a75446c03123d38922e29d4abba85b37b8fa4ed81a2e4`.
Coordinates below are module-local UTF-16 offsets, not bundle offsets.
This review does not prove runtime absence of traffic or replace stub-backed request/TUI checks.

| Lane | Decision |
| --- | --- |
| Prompt markers | Patch required: restore local opt-in for served Agent delegation text. No new hidden classification marker found in reviewed deltas. |
| Host and region fingerprinting | Accept reviewed changes; no new implicit regional prompt/telemetry classification identified. |
| Telemetry and network egress | Accept carryover gates; no new default content-bearing exporter identified. |

## Served-text coverage gap

The unpatched Agent tool description accepts nonblank `tengu_lucky_cerf_text` after only the upstream suppression guard.
It can replace compiled delegation instructions without `CLAUDE_CODE_ALLOW_SERVED_TOOL_TEXT`.
The historical free-text patch was bounded below 2.1.291; later list/WebSearch patches do not cover this function.
This is a pre-existing patch-coverage gap, not behavior introduced in 2.1.301.
The target bump must restore the existing opt-in invariant before release acceptance.
