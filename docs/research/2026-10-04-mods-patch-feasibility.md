# Claude Code Mods: Patch Feasibility and Bundle Interpretation

The [selected migration plan](2026-10-05-privacy-and-invisible-mod-migration-plan.md)
requires invisible native entrypoints/layouts; technical alternatives below are not all selected for implementation.

## Feature Requirements and Evidence

Assess all 30 `patches/*.toml` feature requirements.
Version coverage is metadata, not permission to retire a feature.
A file excluded from v2.1.285 may need a target bump;
its latest implementation still defines a requirement for this assessment.
An inactive version range or unsigned retirement label does not establish abandonment.
Accepted ADRs and digest-bound maintainer retirement decisions remain authoritative;
keeping historical requirements in the assessment does not automatically reinstate them.

Mods are enabled by default from v2.1.287.
Earlier versions shipped experimental function hooks;
the default-on threshold does not prove their absence in v2.1.285.
The public declaration file can lag the installed build.
For example, the retrieved documentation lists `session.append`, telemetry events,
and `agent.spawn.isTeammate`, while the pinned declarations omit them.
Use `/plugin-types` from the exact runtime before implementing a migration.
See [Mods overview](https://code.claude.com/docs/en/plugins/mods/overview#turn-mods-on-or-off),
[Mods reference](https://code.claude.com/docs/en/plugins/mods/reference),
and [types for your build](https://code.claude.com/docs/en/plugins/mods/create#get-the-types-for-your-build).

### Verdicts

| Verdict | Meaning |
| --- | --- |
| Full candidate | Documented seams can plausibly implement the complete requirement; implementation and runtime proof remain necessary |
| Partial | Mods cover a useful subset; a named host behavior remains uncovered |
| Keep patch | The inspected public contract does not expose the seam needed for the requirement |
| Upstream candidate | Inspect the exact upstream build for equivalent behavior before retiring the patch; availability alone is insufficient |

These are feasibility assessments, not runtime proofs or patch retirement decisions.
Preserve feature requirements across any migration.

### Composition, Discovery, and Tool Schemas

`prompt.compose` is a strong replacement for the prompt-vector locator.
Its cache scopes and stable section names improve the adapter surface;
they do not automatically implement this repository's export/rebase/integrity contract.
The main-session boundary and failure path remain the reasons to withhold a full-feature verdict.
Porting repo-owned export/hash logic is implementation work, not an API blocker by itself.
See [System Prompt Overrides](../guides/System-Prompt-Overrides.md)
and [prompt composition types](https://github.com/anthropics/claude-code/blob/2bfb629dfaff0c8318047a4beb93cf1dc5b58b18/mods/types/claude-code.d.ts#L6665).

The [public agents-md mod](https://github.com/anthropics/claude-code/tree/2bfb629dfaff0c8318047a4beb93cf1dc5b58b18/mods/agents-md)
demonstrates ancestor/nested instruction loading through `prompt.context` and Read hooks.
Its fallback/additive mode and content-based deduplication must be compared with our intended behavior.
`$.fs.stat(..., { resolve: true })` supplies a realpath primitive for a hypothetical custom implementation.
However, [ADR-0008](../decisions/0008-keep-native-agents-discovery-and-precedence-together.md)
already adopts native path/content semantics and retires the realpath-only promise.
[ADR-0009](../decisions/0009-bind-native-agents-hook-to-release-graph.md)
keeps only the pinned, verified native callback and closure in the trusted host;
other hooks remain in the restricted worker.
The original full-custom-Mod recommendation overlooked these accepted decisions.
Corrected on 2026-10-05: preserve native discovery, precedence, and trusted callback loading by default.
A custom discovery replacement would require an explicit new boundary decision and runtime proof,
not merely primitives appearing in the public API.

For AskUserQuestion, changing its description or drawing does not change its input schema.
A registered mod tool has a different tool name and contract.
Prove multi-question batching, answer mapping, custom answers, multi-select, and cancellation before accepting such an alternative.
See [tool description types](https://github.com/anthropics/claude-code/blob/2bfb629dfaff0c8318047a4beb93cf1dc5b58b18/mods/types/claude-code.d.ts#L9980)
and [AskUserQuestion rendering types](https://github.com/anthropics/claude-code/blob/2bfb629dfaff0c8318047a4beb93cf1dc5b58b18/mods/types/claude-code.d.ts#L7835).

### Request Overrides and Native State

`TurnStepInput` exposes rewritable `model` and `effort`;
turn identity, message count, and agent identity are pinned.
It does not expose the native request body, SDK-client options, or effort source.
`$.session.model()` reads the model; it does not set the host model registry/state.
`command.run` can intercept built-in commands even though registering their names is refused.
Distinguish a mod-owned command/pane/router from native picker, restore, and capability equivalence.
See [request types](https://github.com/anthropics/claude-code/blob/2bfb629dfaff0c8318047a4beb93cf1dc5b58b18/mods/types/claude-code.d.ts#L10427),
[command interception](https://code.claude.com/docs/en/plugins/mods/reference#commands-and-configuration),
and [Custom Model Slots](../guides/Custom-Model-Slots.md).

Dynamic effort policy on a known `agentId` is possible.
The missing full-feature proof is accepting the caller's effort through the native schema,
mapping it to the correct spawn, and preserving precedence across fork/teammate processes.
Do not infer complete support from either a static `AgentSpec.effort` default or one successful ordinary-agent request.

### Rendering and Durable History

Read basename rendering has the clearest complete candidate:
wrap the engine's drawing and leave stored/model-visible tool results unchanged.
Image output lacks `filePath` in the public union;
correlate `ToolUse.input.file_path` with `ToolResult` by `tool_use_id`, including redraw/resume.
For MCP full-text rendering, preserve errors, non-text blocks, native warning intent, and payload shapes.
The documented per-Text limit is 10,000 characters, so chunking and large-output rendering need proof.
Custom rendering is supported; reproducing the warning is implementation work.
Confirm array, direct-string, and individual-block paths on the target before claiming parity.
See [render-site reference](https://code.claude.com/docs/en/plugins/mods/reference#render-sites)
and [limits](https://code.claude.com/docs/en/plugins/mods/reference#limits).

Live thinking chunks are available from `turn.step`.
Their visible text is separate from the signed block retained by the engine;
a pane/band can show live text without exposing the native inline Thinking renderer.
Test completion, interruption, duplicate rows, and transcript expansion.
See [thinking chunk types](https://github.com/anthropics/claude-code/blob/2bfb629dfaff0c8318047a4beb93cf1dc5b58b18/mods/types/claude-code.d.ts#L10551).

`$.session.messages()` is a summarized, bounded view, not raw JSONL or persisted child transcripts.
The public type limits it to the newest 4,096 entries.
Workflow needs host-linked genuine question answers and immutable provenance, not arbitrary text claiming to be a user answer.
`session.append` must be verified before assuming it fires ahead of filtering/storage transformations.
See [Workflow History](../guides/Workflow-History.md)
and [native provenance record](../records/2026-10-02-workflow-history.md).

## Mods as a Rosetta for Minified Bundles

Yes: public event names, parameter contracts, middleware rules, and built-in mod source
provide semantic anchors for newer bundle surfaces.
The v2.1.88 reference predates these surfaces;
Mods evidence can identify later boundaries that the old source map cannot name directly.
Use it alongside the existing reference, not as evidence that private implementation details are public or unchanged.

### Applying the Anchors

```text
version-pinned public contract and built-in mod usage
  -> event literal and API wrapper in the hashed bundle
  -> event construction, validator, dispatcher, core callback
  -> result consumer and observable behavior
  -> local stub and rendered TUI proof
```

Name-only matches are search seeds.
Executable AST placement plus matching input/output construction identifies a static semantic boundary.
Only runtime probes establish ordering, error behavior, persistence, and visible integration.
Useful stable coordinates include event names, protocol keys, tool names,
`tool_use_id`, `agentId`, section names, and stream/core callback structure.
Minified local identifiers remain version-specific.

The strongest immediate audit uses are prompt composition, tool dispatch/permission boundaries,
model-request streaming, and allowed render sites.
Provider branches, retries, schemas, cache policy, secure storage, and durable history still require host tracing.
`engine.create` and events for Mods API methods govern the mod-facing API;
they do not expose arbitrary private SDK or loader internals.

Keep the read-only v2.1.88 baseline and existing `rationale_ref` rule.
Use Mods contracts and hashed call-path records as supplemental target-version evidence.
This audit adds no locator tooling or runtime instrumentation.

## Migration Evidence Required

Before retiring a patch, export the target's declarations and exercise the affected interactive TUI path.
Use local model and transport stubs for API interactions.
Include restart, reload, resume, subagents, and platform paths when they belong to the requirement.
Keep patch-obligation evidence linked to the replacement implementation.
For partially covered features, retain the remaining host patch and specify the split explicitly.

| Feature group | Required behavior proof |
| --- | --- |
| Memory and prompt composition | Parent/root/nested/extra-directory sentinels; additive/fallback modes; symlink identity versus distinct same-content files; edit/reload/clear; main/subagent/teammate scope; no-op request bytes; sparse override/export/rebase; malformed/stale manifests produce zero requests |
| Read and MCP rendering | All six Read result shapes; image call/result correlation; path separators; redraw/resume/errors; full long MCP text, warnings, non-text/structured results; unchanged model-visible tool data |
| Model/effort/context/resume | Picker and command paths; actual model/effort in captured requests; CLI/Agent/session/slot/env/default priority; ordinary/fork/teammate paths; unsupported-effort retry and notice; accounting/auto-compaction thresholds; restart and resume |
| Native transport/signatures | Beta/nonbeta create and count-token routes; per-model URL/credential headers; global route receives none; signed/redacted thinking removed only on intended endpoints; multi-step streaming/tool responses |
| Keychain | Real Darwin temporary Keychains/default-store sentinel; startup/prefetch/login/read/save/refresh/delete/doctor; resume/plugin-eval; inaccessible-store failure; rendered launcher exit |
| Scheduling/channels/interrupts | Busy/idle timer ordering; pasted contents and list/lifetime; channel provider/feature/allowlist/managed/approval gates; Escape handoff, unrelated background survival on Ctrl+C, explicit agent kill |
| Thinking/footer | Multiple thinking chunks, final answer, tool call, interruption; no duplicate committed row; expanded transcript; hide/show and keyboard actions; actual external statusLine JSON |
| Durable and Workflow history | Exit/resume raw REPL and child tool results; genuine question UI answers; immutable worker snapshot, later-input isolation, bounds/omission disclosure, assignment origins, remote paths, native classifier linkage |
| Privacy and experimental tools | Separate collector and local trace-file sinks; request author identifiers; Nu cwd/structured output and refusal; C# stdout/stderr/nonzero/background rejection/temp cleanup; sandbox outside-write and unavailable-sandbox failures |

Hook failure is a behavior to verify:
Mods skip hooks that fail before `next`, unless an error handler supplies a result.
A migration that needs to reject stale settings, preserve privacy, or enforce a schema must test that failure path.
See [hook failure behavior](https://code.claude.com/docs/en/plugins/mods/events#handle-a-hook-that-fails).
